# FaceTrack portal

The admin portal: a React 18 + TypeScript (strict) single-page app built with Vite (requirements §13, standards/07, standards/08).

## Stack

| Concern | Library |
|---|---|
| UI | shadcn/ui (Radix) on Tailwind CSS 4, lucide-react icons, Recharts |
| Server state | TanStack Query 5. All API data lives here; there is no global store |
| Tables | TanStack Table 8, through the one shared `DataTable` (server-side paging and sort, CSV export) |
| Forms | React Hook Form + Zod; API field errors are shown under the matching inputs |
| API client | Generated by orval from `docs/openapi.yaml` into `src/api/generated/`. Never edit it by hand |
| Live updates | One `/ws/live` socket (`LiveFeedProvider`) that writes into the query cache |
| Live video | WebRTC (WHEP) from MediaMTX, using a short-lived token from `GET /cameras/{id}/live` |
| Tests | Vitest + React Testing Library + MSW; Playwright for end to end |

## Layout

```
src/
  api/          client.ts (axios: cookie session, CSRF header, error normalising), media.ts (image URLs), generated/
  components/   ui/ (shadcn), common/ (DataTable, StatusBadge, ConfirmDialog, providers…), <feature>/
  hooks/        one hook file per resource (useEmployees, useAttendance, …), useAuth, useLiveFeed, useUrlState
  layouts/      AppLayout (sidebar + top bar), AuthLayout
  pages/        one folder per §13 screen
  routes/       router (lazy pages), guards (signed in, permission), navigation (role menu)
  lib/          formatting (UTC → configured timezone), labels, zod schemas, live message handling, WHEP
  test/         MSW server, fixtures, render helper
e2e/            Playwright tests against a running backend
```

## Screens (§13)

| # | Screen | Route | Notes |
|---|---|---|---|
| 1 | Login | `/login`, `/forgot-password`, `/reset-password` | The AD button is shown only when `auth.ldap_enabled` is on |
| 2 | Dashboard | `/dashboard` | KPIs, charts, live event feed and camera strip from `/dashboard/summary` and `/ws/live` |
| 3 | Live view | `/live` | 1/4/9/16 tiles over WebRTC with recognition boxes; click a tile to expand |
| 4 | Employees | `/employees` | Search, filters, bulk import (Excel/CSV + photo ZIP) |
| 5 | Employee profile | `/employees/:id` | Details, face gallery, enroll (upload, or webcam with face-guide oval and quality hints), attendance calendar, leave |
| 6 | Cameras | `/cameras` | Card or table view; add/edit drawer with connection test, snapshot, ROI editor, FPS and threshold sliders |
| 7 | Attendance | `/attendance` | Daily table with snapshot on hover, correction dialog, manual entry |
| 8 | Monthly register | `/register` | Employee × day letters and totals (from `/attendance/register`) |
| 9 | Unknown faces | `/unknown-faces` | Grouped by similarity; assign (optionally add to gallery) or dismiss |
| 10 | Event log | `/events` | Filters; void a recognition with a reason |
| 11 | Corrections | `/corrections` | Pending, approved and rejected; old vs new; approve or reject with a comment |
| 12 | Reports | `/reports` | Eight report types, filters, summary + chart + preview, Excel/PDF export job, scheduled emails (Admin) |
| 13 | Settings | `/settings` | General, organisation, shifts, holidays, recognition, retention, notifications, integration (payroll/HR settings, API keys, run now), users and roles |
| 14 | Audit log / My attendance | `/audit`, `/me` | Admin audit trail; employee self-service with calendar, totals and correction requests |

The menu and routes follow the user's permissions from `/auth/me`. The API enforces the same rules, so hiding a screen is only a convenience.

## Behaviour notes

- **No business logic in the browser:** status, late minutes, worked hours and recognition decisions are shown exactly as the API returns them (standards/07).
- **Times:** the API sends UTC. The portal shows times in the `timezone` from `/auth/me` (setting `general.timezone`). Times typed into forms are converted back to UTC.
- **Status display:** always colour plus text (`StatusBadge`).
- **Destructive actions:** go through `ConfirmDialog`. Biometric erasure and employee deletion also require typing the employee code.
- **Settings:** lowering a recognition threshold or quality gate asks for an explicit confirmation before saving.
- **Theme:** light (warm white / cream surfaces, one deep corporate-blue accent) is the default for every user, whatever the operating system's dark-mode setting. Dark and System stay selectable in the user menu; the choice is kept per browser in `localStorage` under `facetrack.theme.v2` (the old `facetrack.theme` key is ignored and removed, so browsers that had "system" saved start on light). Colours live only as tokens in `src/index.css` (`:root` = light, `.dark` = dark); components use the tokens, never raw colours. Text pairs in the light theme are at least 4.5:1 (WCAG AA), including status text on its own badge tint.
- **Fonts:** the operating system's UI font, with no web fonts (on-premise, no external requests): `"Segoe UI", system-ui, -apple-system, "Helvetica Neue", Arial, sans-serif`, set as `--font-sans` in `src/index.css`. On Windows this is Segoe UI. Body text is 15px, tables, labels and navigation 14px (`text-sm`), and `text-xs` is raised to 13px for secondary text.
- **UI components:** the shadcn/ui components are written for React 19. On React 18 they are wrapped with `fwd()` (`src/lib/forwardRef.ts`) so that refs reach the DOM; this matters for `asChild` triggers, Radix animations and form focus.

## Develop

```bash
npm ci
cp .env.example .env.local      # optional; empty values = same origin
FACETRACK_BACKEND_URL=http://localhost:8000 npm run dev   # proxies /api and /ws to the backend
npm run gen-api                 # after backend schema changes (or `make gen-api` from the repo root)
npm run lint && npm run typecheck && npm test && npm run build
```

End-to-end tests need a running backend with a **non-production** Super Admin:

```bash
E2E_USERNAME=admin E2E_PASSWORD=... npm run build && npm run e2e
```

## Deploy

The portal is built into the edge Nginx image (`infra/nginx/Dockerfile`, a Node build stage followed by `nginx:stable-alpine`). That image also serves TLS and proxies `/api`, `/ws`, `/webrtc` (WHEP to MediaMTX) and `/grafana`. See `docs/runbook.md`.
